我要从零创建一个 Rust/WASM WinUI SDK 项目，由 TypeScript 调用。

最终目标：
依据微软 WinUI 的源实现，还原控件外观、布局、交互、
材质和动画。以固定版本的官方 WinUI Gallery 作为
成果展示、示例组织和原生对照验收的基准。

这是一项新的独立项目。请在新项目目录中工作，
先检查目录与已有文件，保留用户已有内容。

实施阶段、依赖顺序和阶段验收参见
[实现顺序与关键要点](../docs/implementation-roadmap.md)，其中附有微软架构参考。
该路线中的阶段目标不代表已完成功能；具体范围与约束仍遵循本文件。

一、明确架构

Rust 负责：
- 控件树、布局、属性及内部状态。
- 主题资源、模板和视觉状态。
- 材质效果、动画时间线及中断规则。
- 命中测试、渲染资源和绘制调度。

TypeScript 负责：
- 对外 SDK、业务数据和事件回调。
- 浏览器宿主适配。
- 演示应用及 React 组件适配。

基础 TS SDK 不依赖 React。
React 包装建立在同一个 SDK 上，不维护另一套控件实现。

前端技术栈要求：
- 使用初始化时最新稳定版的 TypeScript、React、React DOM 和 Vite，
  Gallery 实验应用采用 React + TypeScript + Vite。
- 安装前从 npm 官方注册表核实各包的 latest 稳定版本及兼容要求，
  不凭记忆填写版本，不默认使用 beta、RC、canary 等预发布版本。
- React 与 React DOM 版本保持一致，配套类型包、Vite React 插件
  和 Node.js 版本满足所选版本的兼容要求。
- 在项目文档中记录核实日期及实际安装版本，提交依赖锁文件，
  保证可重复安装；后续升级显式执行并验证，不在每次构建时浮动更新。
- 开启 TypeScript strict 检查，保证 TS SDK、React 适配和 Gallery
  均通过类型检查与 Vite 生产构建。

浏览器焦点外观要求（全局约定）：
- 全局屏蔽浏览器默认的焦点黑框、outline 和 focus-visible ring，
  包括 Gallery、宿主适配和无障碍 DOM 投影，避免叠加在 WinUI 绘制上。
- 保留真实焦点、Tab/方向键导航和无障碍语义，不能通过 blur、
  禁止聚焦或拦截 Tab 来隐藏黑框。
- 此约定也包括 Rust 在 Canvas 内模拟的焦点黑框，不只处理 CSS。
  鼠标和键盘聚焦均不绘制黑色焦点描边；保留选中指示条、悬停、
  按下等状态。这一项作为用户明确指定的原生外观例外登记。
- 将上述规则纳入实际浏览器验证，后续新增页面与控件同样遵守。

浏览器默认使用 Rust/WASM + Canvas2D，Gallery 所有页面同样默认 Canvas2D。
WebGL2 等后端仅作为用户显式选择的可选项，不能因页面类型自动切换。
核心算法与控件逻辑应尽量独立于具体后端和宿主。

React 公共组件直接接收类型化属性，例如 `<TextBlock text="Hello" />`、
`<Button text="Save" enabled={enabled} onClick={save} />`，
不要求额外的 `options={{...}}` 包装；运行示例、源码面板和文档保持一致。

四、按原实现建立可复用 SDK

阅读 C++ 行为、XAML 模板和 SDK 资源后再实现对应控件。

建立：
- 控件节点及属性系统。
- Measure/Arrange 布局契约。
- 资源字典和主题解析。
- 模板实例化与命名部件。
- VisualState 和动画执行机制。
- 输入、焦点和命中测试。
- 渲染后端接口与资源生命周期。

公共接口按 Rust 和 TS 的使用方式设计，
保持原生可观察语义，无需复制完整 COM/WinRT 对象体系。

优先构建期提取所需 XAML，转换为有来源信息的中间描述，
由 Rust 执行对应语义。
不要求首阶段实现完整通用 XAML 运行时。
不支持的节点、绑定或表达式必须报告，不能静默丢弃。

材质应移植配方与效果图；
动画应移植时长、延迟、曲线、关键帧、
状态切换、中断、反向、取消和卸载行为。

五、TS SDK 边界

- Rust 持有控件内部状态。
- TS 使用稳定句柄创建、更新和销毁控件。
- 支持属性变更批量提交。
- 动画在 Rust 内推进，避免每帧由 TS 逐属性驱动。
- 明确所有权、失效句柄、回调取消和资源释放。
- 区分通知事件与允许同步取消的事件。
- 明确事件重入及销毁期间的行为。
- 业务对象及 JS 函数由 TS 管理，通过 ID 和回调关联。
- 公共封闭属性使用有文档的枚举。
- 提供完整 TypeScript 类型声明和可运行示例。

公共 API 的易用性要求：
- 常见操作应能用少量、直观的调用完成；提供合理默认值，
  最简单示例只要求必要参数，高级能力通过可选配置逐步开放。
- 简化调用不能删减控件功能、事件、状态或自定义能力。
  常用接口与高级接口应基于同一实现，均具有完整类型和文档。
- 初始化和挂载流程应统一、简洁；WASM 加载完成后，
  不要求业务方为每个控件重复处理底层初始化和资源注册。
- 公共 API 提供清晰的控件对象或类型化句柄，封装内部节点 ID、
  指针、内存地址、命令编码和跨语言数据转换。
  常规业务调用不应要求用户手写协议、JSON 或资源释放顺序。
  必要的 dispose/unmount 应简单明确，高级批处理应可选使用。
- 提供创建、读取/更新属性、事件订阅/取消、销毁的完整用法。
  每项 API 同时给出最简单示例与需要时的高级示例，
  Gallery 使用同一套公共 SDK，不通过内部接口绕过设计问题。

封闭字符串属性的导出与类型约束：
- 对主题、按钮样式、方向、对齐、选择模式、动画类型等有限取值，
  必须从 TS SDK 公共入口导出可在运行时使用的具名枚举，
  供调用方通过成员访问并获得 IDE 补全，例如 ThemeMode.Dark、
  ButtonVariant.Accent、HorizontalAlignment.Center。
- 属性类型必须接受对应枚举；不能只导出常量对象，属性却仍接受
  string、裸字符串联合类型、Enum | string 或其他放宽类型。
  直接传入裸字符串、拼错成员或使用不兼容的枚举时，应编译失败。
- 枚举、每个成员和对应属性均需有清晰的 JSDoc，
  说明用途、差异和默认值；默认值、示例、文档及测试同步使用枚举。
- Rust 枚举与 TS 枚举应有明确映射，优先从同一份定义生成或校验，
  避免两端取值、默认值和新增成员发生漂移。
- 文本、业务 ID、URL、资源键、用户输入等开放字符串保持开放类型，
  不为其虚构枚举；HTML/ARIA 原生属性保持平台语义。
- 将公共导出与类型约束纳入验证：合法枚举调用应通过，裸字符串、
  拼错成员和不兼容枚举调用应按预期产生类型错误。

浏览器输入法、剪贴板、无障碍和媒体等能力，
通过宿主适配实现；适配边界必须可检查。

文字布局与裁剪的通用约定：
- 自然 DesiredSize 必须在 Measure 阶段包含物理像素取整预算，并经父布局容器传播，不能只在子节点 Arrange 时向上取整。
- Measure 的换行约束必须与 Arrange 可保证的内容宽度一致，避免排列阶段才增加行数而沿用旧高度；半像素边界要避免浮点噪声导致边缘反向取整。
- 修复此类问题优先修改共享布局与文字链路，不通过给单个 Gallery 示例硬编码宽高或关闭裁剪来掩盖。
- 新增验证覆盖嵌套 Grid/StackPanel、多个文字控件、长标签、字号变化、分数 DPR 与内容高度同步。显式尺寸、裁剪及截断仍按调用方约束执行。

新增控件内联按钮和滚动宿主约定：
- TextBox/PasswordBox 内联按钮的命中区与背景遮罩须分开；按 C++ SizeChanged 的正方形规则和模板内部 Margin/BorderThickness 推导，宿主使用 Rust 投影的矩形，不能另写常量大小。
- 多行聚焦底边按物理像素和原生圆角边界验证，在高度、DPR 改变后保持厚度；禁止只验证单行 100% 缩放。
- SDK 应用内全局滚动条默认随统一 SDK 初始化自动接入，React Provider 同样自动接入，业务调用方不需要刻意安装。全局滚动条复用 Rust ScrollViewer；浏览器宿主只负责 DOM 发现、尺寸/偏移和原生内容适配，不再实现另一套 CSS/JS 滑块状态与动画。保持原生滚轮、触摸、选区与业务 DOM 生命周期，并提供卸载恢复。
- 外部 DOM 不可作为当前 Rust Canvas 的背景采样源时，必须明确使用原生资源 fallback，不宣称已实现网页 Acrylic 采样。
- ProgressBar 等细矢量控件验证必须包含默认厚度、可见范围裁剪后的端点、加高尺寸和分数 DPR；使用独立覆盖率检查，避免仅靠大区域平均误差掩盖方端点、二次缩放或锯齿。
